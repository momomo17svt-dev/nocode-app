# API連携ガイド

## APIトークンの発行

システム管理者でログインし、左メニューの「システム設定」→「APIトークン」から発行します。

- 用途名: どの外部ツールで使うか分かる名前
- 利用ユーザー: APIが引き継ぐユーザー権限
- 有効日数: 1～365日
- 閲覧のみ: 初回は有効を推奨

トークン本体は発行直後の1回だけ表示されます。データベースにはハッシュのみ保存されるため、紛失した場合は古いトークンを無効にして再発行してください。

## 呼び出し方法

HTTPの`Authorization`ヘッダーへBearerトークンを指定します。Docker版では、通常は画面と同じURLの`/api`を利用できます。

```bash
curl -H "Authorization: Bearer 発行したトークン" \
  "http://localhost:5173/api/apps"
```

APIトークンには選択した利用ユーザーと同じアプリ・レコード権限が適用されます。「閲覧のみ」のトークンでは、GET・HEAD・OPTIONS以外の更新操作は拒否されます。

レコード一覧の例です。`appId`は対象アプリのURLまたはアプリ一覧APIで確認できます。

```bash
curl -H "Authorization: Bearer 発行したトークン" \
  "http://localhost:5173/api/records?appId=アプリID&page=1&pageSize=50"
```

更新可能トークンでレコードを更新する場合は、取得したレコードの`version`を`expectedVersion`へ指定します。他の利用者が先に更新していた場合は409エラーとなるため、最新データを再取得してからやり直してください。

```json
{
  "data": { "status": "完了" },
  "expectedVersion": 3
}
```

## 無効化と監査

不要になったトークンは「システム設定」で無効化します。発行・無効化は監査ログへ記録され、一覧では最終利用日時を確認できます。利用ユーザーの無効化、権限変更、パスワード変更を行った場合も、そのユーザーに紐づく既存トークンは利用できなくなります。

トークンをURL、ソースコード、Git、チャット本文へ埋め込まないでください。外部ツール側のシークレット管理機能またはアクセス制限された環境変数へ保存してください。
