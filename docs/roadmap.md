# ロードマップ

*[English version](roadmap.en.md)*

[既知の課題](known-issues.md)が「今できないこと」の一覧なのに対して、こちらは「やる予定」です。日付は約束ではありません。上にあるものほど優先度が高い、という順序だけが意味を持ちます。

各項目の末尾にある難易度は、着手する人への目安です。

- **S** — 変更が1〜2ファイルに収まり、既存のテストが手本になる
- **M** — 複数レイヤーに触れるが、設計判断は済んでいる
- **L** — 設計から決める必要がある

Issueが立っているものは[こちら](https://github.com/momomo17svt-dev/nocode-app/issues)。`good first issue`ラベルが付いているものから拾ってください。

## やらないこと

判断済みの非目標です。提案は歓迎しますが、方針を覆すだけの理由が必要です。

- **マルチテナントSaaS化** — 1組織1インスタンスの前提を崩すと、権限モデルとバックアップ設計の全面的な作り直しになります
- **常時インターネット接続を前提とした機能** — 閉域ネットワークで動くことがこのプロジェクトの存在理由です
- **クラウドLLMの必須化** — AI機能は常に任意で、ローカルLLMだけで完結できる状態を保ちます
