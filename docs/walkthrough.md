# 実装ウォークスルー (Walkthrough)

仕様書（`docs/仕様書.md`）のMVPに対する実装内容のまとめです。

## アーキテクチャ
- **Backend**: NestJS 11 + Prisma 7 + PostgreSQL（`@prisma/adapter-pg`）、JWT認証、bcrypt
- **Frontend**: React 19 + TypeScript + Vite + React Router 7
- **構成**: `backend/`（API）, `frontend/`（SPA）, `storage/attachments/`（添付実体）, `docs/`

## 認証・認可（仕様の最重要要件）
- 認証: `JwtAuthGuard` を全業務APIに適用。`AuthService` は bcrypt 比較・無効化ユーザー拒否・汎用エラーメッセージ。
- グローバルロール: `RolesGuard` + `@Roles()` で `SystemAdmin / AppCreator / StandardUser / Viewer` を制御。
- **アプリ別認可**: `PermissionService`（`backend/src/permissions/permission.service.ts`）が仕様5章の判定順を実装。
  1. システム管理者 → 全許可
  2. アプリ所有者 → 全許可（管理含む）
  3〜5. ユーザー個別 / 所属グループ（OR結合）/ 全ユーザー公開 の権限を結合
  6. 該当なし → 403
  - 閲覧ユーザー(Viewer)は追加/編集/削除/管理を強制的に無効化。
- すべてのレコード/フィールド/ビュー/添付/公開設定APIで `permission.assert(...)` によるバックエンド認可を実施（BOLA対策）。
- フロントは `GET /api/apps/:id` が返す `myPermission` を使ってボタン表示を切替（あくまでUX目的、最終判定はサーバ）。

## ライブ検証結果（権限テスト）
実DB + 実APIに対して以下を確認済み（`docs/permission-test-report.md` 参照）:
- 未認証 → 401、不正パスワード → 汎用メッセージ
- viewer は `/users`・アプリ作成・レコード追加が 403、admin/権限保有者は成功
- viewer の有効権限 = 閲覧のみ、user1（営業部）= 閲覧+追加+編集（公開設定のOR結合が機能）
- CSVエクスポートは管理権限保有者のみ（user1=403, admin=成功）、カンマ/改行/引用符を正しくエスケープ
- レコード更新で変更履歴を記録
- 添付: UUID保存名・ダウンロードで原名復元・未認証DLは401・閲覧権限で認可
- CSVインポート: 必須未入力行をエラーとして返却
- 監査ログに各操作が記録される

## 追加実装（レコード単位権限・アプリ操作UI）
仕様のアプリ単位権限に加え、業務向けに以下を追加・検証済み。
- **レコード公開範囲（作成者本人限定）**: アプリ設定に「閲覧範囲」「編集範囲」を追加（`all` / `owner`）。`App.recordViewScope` / `recordEditScope` 列で保持。
  - `owner` 時、管理権限を持たないユーザーは**自分が作成したレコードのみ**閲覧/編集/削除可能。一覧取得は `createdBy` で絞り込み、詳細/更新/削除/コメント/添付は作成者照合で403。これにより「一般ユーザーは入力のみ・他人のレコードは改ざん不可」を実現。
  - 判定は `RecordsController.assertRecordScope()` / `AttachmentsController.assertViewScope()`、範囲取得は `PermissionService.getRecordScope()`。
- **アプリ削除・複製のUI**: アプリ設定画面（管理権限保有者のみ）に「アプリを複製」「アプリを削除（二重確認）」ボタンを追加。バックエンドAPI（`DELETE /api/apps/:id`・`POST /api/apps/:id/duplicate`、ともに `canManage` 必須・監査記録）に接続。

ライブ検証: owner設定で user1 は全5件中**自分の3件のみ閲覧**、creator作成レコードの閲覧/編集/削除は**すべて403**、`all`に戻すと全件閲覧に復帰。複製はフィールド定義をコピー、複製アプリ削除成功、管理権限なしのアプリ削除は403。

## kintone風 追加機能（第3弾）
1. **一覧ビュー** — 複数の保存ビューを切替（共有/自分用）。ビューごとに 表示列・絞り込み条件（含む/等しい/大なり等）・並び順 を保存。一覧の列ヘッダクリックでソート、行チェックで**一括削除**。(`POST /api/records/bulk-delete`)
2. **集計・グラフ** — 一覧の「集計・グラフ」タブで、任意フィールドでグループ化し件数/合計を**棒・円グラフ**表示。外部CDN不使用の自前SVG（`components/Chart.tsx`）。
3. **プロセス管理（ワークフロー）** — アプリ設定「プロセス管理」タブでステータス項目と遷移アクション（from→to＋ボタン名）を定義。`App.processConfig`(JSON)に保持。レコード詳細に現在ステータス表示＋**アクションボタン**を出し、押すと次状態へ遷移。
4. **フィールド機能の充実** —
   - 計算フィールド: サーバ側で数式評価（`compute.util.ts`、eval不使用の再帰下降パーサ。+ - * / と括弧、フィールドコード参照）。作成/更新/CSV取込で自動計算。
   - 自動採番: アプリ×フィールド単位の連番を`settings`テーブルで採番（接頭辞・0埋め桁数）。更新時は採番を保持。
   - 初期値・単位・桁区切り・最大文字数 をフィールド設定で指定可。

ライブ検証: 計算 price*qty=300→(qty=5に更新で)500、自動採番 INQ-0001/INQ-0002・更新後も保持、一括削除2件、ビュー(条件配列/列/並び順)保存・取得、プロセス設定保存・取得 をすべて確認。
