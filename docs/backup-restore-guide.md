# バックアップ・復元ガイド

## バックアップ対象

完全なバックアップには次の4点が必要です。

1. `export-db.bat`で作成する`migration/nocode_db.sql`
2. `storage/attachments`（添付ファイル）
3. 必要なら`storage/tiles`（オフライン地図）
4. 移行先へ安全に渡した`.env`（公開リポジトリや共有領域へ置かない）

## 移行と復元

移行元でサービスを止めるか更新がない時間帯に`export-db.bat`を実行し、プロジェクトフォルダ全体をコピーします。移行先のDBが空であることを確認してから、Dockerは`start_docker.bat`、Dockerなしは`setup.bat`を実行します。`migration/nocode_db.sql`は新規DB作成時だけ自動復元されます。既存DBを意図せず上書きしません。

## 復元確認

- 管理者でログインできる
- アプリ件数と主要レコード件数が移行元と一致する
- 添付ファイルを1件ダウンロードできる
- 監査ログと権限設定が表示される
- 新しいテストレコードを作成・削除できる

復元確認後まで移行元とバックアップを削除しないでください。定期的に別媒体へ世代管理し、少なくとも四半期ごとに別DBへの復元試験を行います。

GitHub ActionsではE2E用DBを毎回ダンプし、別名の空DBへ復元してスキーマとデータを自動照合します。これは本番バックアップの保管確認を置き換えるものではありません。
