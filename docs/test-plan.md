# テスト計画 (Test Plan)

## 1. 単体テスト (Unit Tests)
- 対象: バックエンドのビジネスロジック、権限判定ロジック、ユーティリティ関数。
- ツール: Jest (NestJSの標準機能を使用)
- 目標: `PermissionGuard` や権限判定サービスの条件分岐を網羅する。

## 2. API結合テスト (Integration Tests)
- 対象: REST APIエンドポイント。
- 内容: ダミーデータベースを用いたリクエスト/レスポンスの検証。
- ポイント:
  - 認証なしでのアクセスが `401 Unauthorized` になること。
  - 権限のないユーザーでのアクセスが `403 Forbidden` になること。
  - 不正なJSONB構造によるエラー処理。

## 3. E2Eテスト (End-to-End Tests)
- 対象: フロントエンドからバックエンドまでの通し動作。
- ツール: Playwright または Cypress
- 内容:
  - ログイン〜アプリ作成〜フォーム定義〜レコード追加の一連のフロー。
  - 異なるユーザーロール（管理者、一般ユーザー）での画面表示の違いを確認。

## 4. 権限テストマトリクス
- システム管理者、アプリ作成者、一般ユーザー、閲覧ユーザー×アプリ公開設定（全公開、非公開、特定ユーザー等）の組み合わせで、CRUD操作の可否をマトリクス化し、自動テストで検証する。

## 5. オフライン・環境テスト
- **Windows 10 LAN環境シミュレーション**: インターネットから切断された状態で正常に画面描画、フォント読み込み、ファイルアップロード、データ保存が行えるか手動で確認する。
