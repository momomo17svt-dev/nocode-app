# セキュリティ設計レビュー (Security Review)

完全オフライン環境であっても、内部不正や悪意ある操作を防ぐための対策を実施する。

## 1. 認証とパスワード保護
- **パスワード保存**: 平文保存は厳禁。`bcrypt` などの強力なハッシュ関数を利用する。
- **セッション管理**: JWT(JSON Web Token) またはセキュアなCookieベースのセッションを利用する。XSSを考慮し、トークンの保存場所には `HttpOnly Cookie` の使用を推奨する。
- **エラーメッセージ**: ログイン失敗時、「ユーザーが存在しない」「パスワードが間違っている」を区別せず、「ログイン情報が正しくありません」と汎用的なメッセージにする。

## 2. 認可とアクセス制御
- APIの各エンドポイントに NestJS の Guards を配置し、**BOLA (Broken Object Level Authorization)** を防ぐ。
  - 例: ユーザーAが、権限のないアプリBのレコードにアクセスできないことを徹底。

## 3. ファイルアップロードとパストラバーサル対策
- **ファイル名サニタイズ**: 保存ファイル名はシステム側で `UUID` 等を生成して付与し、元のファイル名はDBメタデータとしてのみ保持する。
- **パストラバーサル**: リクエストパラメータからファイル名を直接指定させてファイルシステムへアクセスするような実装を避ける。（例: `../../Windows/System32` のような入力を無効化）。

## 4. CSVエクスポート権限
- 大量データ持ち出しのリスクを軽減するため、CSVエクスポートは「アプリの管理権限」または特定の「エクスポート権限」を持つユーザーのみに制限する。
- 実行時は必ず監査ログに記録する。

## 5. 監査ログ
- 情報の変更、アクセス、ログイン・ログアウト、CSV出力などの重要イベントをすべて `audit_logs` テーブルに記録し、システム管理者が後から追跡できるようにする。
