# 既知の課題・制約 (Known Issues)

MVPとして仕様の主要要件を満たしていますが、以下は今後の改善余地です。

## 機能面
- **計算フィールド(calc)・自動採番(auto_number)**: サーバ側で実装済み（calcは四則演算+括弧+フィールド参照、auto_numberは接頭辞+0埋め連番）。calcは関数(SUM等)や日付計算には未対応。
- **ビュー(保存済みビュー)**: 切替・表示列・絞り込み条件・並び順の保存UIを実装済み。絞り込みは AND 結合のみ（OR/グループ化は未対応）。フィルタ/ソートはLAN規模前提でクライアント側処理。
- **集計グラフ**: 件数/合計の棒・円グラフを実装（自前SVG）。クロス集計（2軸）や折れ線・期間集計は未対応。保存（ダッシュボード化）は未対応。
- **プロセス管理**: ステータス遷移＋アクションボタンを実装。作業者割当・条件分岐・並行ルートは未対応。
- **ユーザー選択/グループ選択フィールド**: IDを保存し詳細でログインID/グループ名に解決して表示。複数選択は未対応。
- **ルックアップ／関連レコード**: 他アプリ参照（kintoneのルックアップ）は未対応。
- **CSVインポートのエンコーディング**: フロントでUTF-8優先・文字化け時にShift_JISへフォールバック。複雑な混在ファイルは要検証。

## セキュリティ・運用
- **トークン保存**: フロントは `localStorage` にJWTを保持（仕様の推奨は HttpOnly Cookie）。LAN内利用前提のMVP実装。XSS耐性を高めるならCookie方式への移行を推奨。
- **JWT秘密鍵**: ハードコードのフォールバックは撤去済み（`auth/jwt.constants.ts`）。`JWT_SECRET` 未設定／初期プレースホルダ(`change_me...`)のままだと起動時に例外で停止する。`.env` に固有のランダム値（例: `openssl rand -hex 32`）を設定すること。
- **添付アップロード権限**: レコード編集権限（または作成者本人＋追加権限）で許可。MIMEタイプの厳格な検査は最小限（サイズ上限20MB）。
- **CORS**: 本番環境で`CORS_ORIGINS`が未設定の場合はクロスオリジン通信を許可しない。別ドメインのフロントエンドから利用する場合だけ、許可するオリジンを明示する。
- **リバースプロキシ**: Docker版は同梱Nginxの1段だけを信頼する。bat版を別のリバースプロキシ配下へ置く場合は、接続経路を限定したうえで`TRUST_PROXY=1`を設定する。

## テスト
- 単体テスト(`*.spec.ts`)を実ロジックへ置き換え済み（`npm test` で全27スイート・251件green）。
  - 純粋ロジック: `compute.util`（計算式・ルール表・自動採番）96%、パストラバーサル防御 `storage.util`。
  - セキュリティ中核: `permission.service`（アプリ別認可・owner/org公開範囲・組織ツリー）93%、`auth.service` 100%。
  - サービス: records / users / groups / fields / views / apps / attachments / audit-logs / app-permissions。
  - コントローラ: 認可ゲート（権限なし時にサービス未呼び出し）・委譲・監査ログ記録・レコード単位スコープを検証。
- E2E（実DB結合）整備済み（`npm run test:e2e` で全4スイート・22件green）。`pretest:e2e` が専用DB `nocode_test_db` を自動作成＋マイグレーションし、開発用 `nocode_db` には触れない。supertest で実HTTPを叩く。
  - 認証フロー（login成功/失敗・無効化ユーザー拒否・トークン無し401・改ざん401・パスワード変更の前後）。
  - 認可の通し検証（アプリ権限ゲート403/200・Viewerの書込拒否・SystemAdminバイパス・レコード単位owner範囲のview/edit）。
  - レコードのライフサイクル（自動採番連番・計算フィールド・更新時の採番保持/履歴・検索/絞り込み・削除）。
- 未カバー領域: AI/RAG(`ai`,`llm`,`embedding`)、ダッシュボード、通知、`records`の一部経路（findRelated/コメント/CSVエクスポート等）。ライブAPIの手動検証は `permission-test-report.md` 参照。
- フロントエンドのlintはエラー0件だが、既存のReact Hook依存配列に関する警告が19件残っている。挙動変更を伴う可能性があるため、画面ごとの回帰テストと合わせて段階的に解消する。

## パフォーマンス
- レコードの検索/フィルタはアプリ単位で全件取得後にメモリ上で絞り込み（LAN・中小規模前提）。大規模データではJSONBインデックス/SQL側フィルタへの移行を検討。
- 現在のフロントエンド主要JavaScriptは圧縮前約797KB（gzip約223KB）。初回表示をさらに速くする場合は画面単位の遅延読み込みを導入する。
