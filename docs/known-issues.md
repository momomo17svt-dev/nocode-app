# 既知の課題・制約 (Known Issues)

## 機能面

- 計算フィールドは四則演算・括弧・フィールド参照・基本関数（`if` `min` `max` `abs` `round` `floor` `ceil`）と、明細テーブルの集計（`sum(明細.列)` `avg(明細.列)` `count(明細)`）に対応しています。日付どうしの差分計算には未対応です。
- ルール表の比較は固定値のほか、`valueField`で別項目の値も指定できます（例: 在庫数 < 発注点）。保存ビューの絞り込み条件は固定値のみで、項目どうしの比較はできません。判定結果を計算フィールドに出し、その値でビューを絞ってください。
- 保存済みビューの条件はAND結合です。OR条件や条件グループ化は未対応です。
- 一覧タブはDB側で検索・条件・並び替え・50件単位のページ分割を行います。かんばん・カレンダー・地図・進捗・グラフは表示対象全件を取得するため、非常に大きなアプリでは表示対象を保存済みビューで絞ってください。
- 集計グラフは件数・合計の棒/円グラフです。クロス集計、折れ線、期間比較は未対応です。
- プロセス管理はステータス遷移と承認者に対応しています。条件分岐や並行ルートは未対応です。
- ユーザー/グループ選択は単一選択です。

## セキュリティ・運用

- 認証JWTはHttpOnly Cookieに保存し、更新リクエストはCSRFトークンを検証します。旧版の保存済みJWTは初回表示時にCookieへ交換して削除します。API連携用Bearer応答は既定で無効です。
- 最初の管理者は、管理者が存在しない間だけ有効な初回セットアップ画面から作成します。作成後は同じエンドポイントが403になります。誰もログインできなくなった場合の復旧手段は、DBを直接操作するか作り直すことだけです（画面からのパスワード再発行はありません）。
- ログイン失敗の一時ロックは、ログインIDとIPの組み合わせ単位です。解除を待てない場合はDBの`LoginThrottle`を削除します（手順は[Docker起動ガイド](docker-guide.md)）。管理画面からの解除操作は用意していません。
- `.env.example`の`POSTGRES_PASSWORD`と`JWT_SECRET`は、コピーしただけで起動できるように`sample_only_`で始まる公開値が入っています。1台での試用以外では差し替えてください（Windowsの`start_docker.bat`は自動で置き換えます）。サンプル値のまま起動している間、バックエンドは起動時に警告を出します。
- DockerをHTTPS終端の背後で公開する場合は`AUTH_COOKIE_SECURE=true`にしてください。HTTPのLAN内利用では`false`のままです。
- 添付・画像・ナレッジ文書はシグネチャ、拡張子、MIMEを照合し、実行ファイルを拒否します。ウイルス対策ソフトによる内容スキャンやOfficeマクロ検査は含みません。
- 匿名公開フォームの回数制限は単一プロセスのメモリ内管理です。複数バックエンド構成ではRedis等の共有ストアへ置き換えてください。回数制限に加えて、必須項目と入力量はサーバ側で検証します。
- レコード保存時は、アプリのフィールド定義に無いキーを取り込みません。1値10万文字、複数選択1,000件、サブテーブル1,000行、レコード全体200万文字を上限とし、超過は400で拒否します。保存済みの値は、後から項目を削除しても更新のたびに消えることはありません。
- CSVエクスポートは`=`・`+`・`-`・`@`で始まるセルの先頭にシングルクォートを付け、表計算ソフトが数式として実行しないようにします。本アプリへ取り込み直す際は同じ規則で元へ戻します。他システムへ渡す場合は、この先頭クォートの扱いを確認してください。
- bat版の`setup.bat`は`initdb`を認証方式の指定なしで実行するため、ローカル接続はtrust（無認証）になります。PostgreSQLの既定で待ち受けはlocalhostのみですが、同じPCを他の利用者と共有する場合はDocker版を使うか、`pg_hba.conf`とパスワードを設定してください。
- Docker同梱NginxにはCSP等のセキュリティヘッダーがあります。インターネット公開時はTLS、WAF/ネットワーク制限、集中ログ監視、秘密情報管理を追加してください。
- AI連携を有効にすると設定したOpenAI互換APIへ文書・レコード由来データが送信されます。クラウド接続では組織の情報管理方針と送信先の利用規約を確認してください。
- LLMのAPIキーは設定APIや画面へ再表示しませんが、サーバー設定DBには保存され、DBバックアップにも含まれます。DBとバックアップを暗号化・アクセス制限し、公開リポジトリへ含めないでください。

## テスト

- バックエンド単体テストは認証、CSRF、権限、レコード、アップロード検証、監視を含みます。
- E2Eは専用PostgreSQL DBで認証Cookie/Bearer、権限、レコードのページ分割とライフサイクルを検証します。
- フロントエンドは計算処理、APIの重複排除・CSRF・認証失効、ログインをVitestで検証します。
- CIはDBダンプを別DBへ復元し、スキーマとデータが戻ることまで確認します。
- 未カバーの中心は、外部LLMを必要とするAI/RAG実動作、地図描画、印刷レイアウトの視覚差分です。

## パフォーマンス

- 一覧取得はサーバー側ページ分割、主要列インデックス、短時間GETキャッシュ、同時GET重複排除を使用します。
- 画面単位の遅延読み込みにより初期JavaScriptを分割しています。地図など大きな機能は利用時に読み込みます。
- JSONB全フィールド横断の部分検索はデータ量と文字列量に比例します。数百万件規模では検索専用列や全文検索基盤を検討してください。
